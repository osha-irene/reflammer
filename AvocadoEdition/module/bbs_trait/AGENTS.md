# bbs_trait 구현 지침

- 공통 모듈 규칙은 [`../../docs/module/AGENTS.md`](../../docs/module/AGENTS.md)를 따른다.
- 특성 카탈로그·캐릭터 보유·기간별 사용 이력은 이 모듈의 InnoDB 테이블이 소유한다. Avocado Edition 코어와 StatusExtra는 수정하지 않는다.
- 전투 계산·HP 적용은 `bbs_duel`이 소유한다. 특성 모듈은 `bbs_duel_trait_form`, `bbs_duel_trait_prepare`, `bbs_duel_trait_consume` 필터로만 연동한다.
- 최대 슬롯은 전체 캐릭터 공통이며, 기본 개방 수와 캐릭터별 확장 슬롯을 합쳐 각 캐릭터의 현재 수용량을 계산한다. 슬롯 축소는 기존 보유를 회수하지 않으며, 초과 상태에서 지급할 때 기존 특성과 교체한다.
- 캐릭터별 추가 슬롯은 `slots` 테이블에 기록한다. 상점 판매용 `특성 슬롯 확장` 아이템은 구매 뒤 인벤토리에서 사용하며, 1회 사용에 1개를 영구 개방하고 최대치에서는 소모하지 않는다. 아이템 사용은 `item_type_options`와 `inventory_use_dispatch` 훅으로 처리하고 코어 파일은 수정하지 않는다.
- `특성 습득권`은 아이템 관리의 `it_value`에 연결 특성 ID를 저장한다. 관리자 폼 확장·저장 훅에서 활성 특성을 선택하고, 사용 시 빈 슬롯에 추가하거나 보유 특성 하나를 비교·확정 교체한다. 취소, 검증 오류, InnoDB 트랜잭션 실패 시 아이템은 유지된다. 소유·슬롯 변경과 `item_use` 멱등 영수증은 InnoDB 트랜잭션으로 기록한 뒤 코어 MyISAM 인벤토리를 삭제한다. 영수증은 삭제 실패/중단 뒤 같은 아이템으로 중복 습득하는 것을 막고, 다음 사용 시 잔여 아이템 정리를 재시도한다.
- 특성은 하나당 효과 하나, 캐릭터당 중복 보유 없음, 전투 글 또는 댓글당 최대 한 개다. 사용 제한 `NULL`은 무제한이고 `0`은 사용 불가다.
- 리플 사용은 특성별 `comment_enabled`와 MMB 게시판의 `comment` 범위를 모두 켜야 한다. 리플 특성은 새 MMB 댓글에 하나만 발현하고, 익명 사용은 거부한다. 효과는 수치 판정에 반영하지 않으며 캐릭터·특성·기간 사용량만 공유 차감한다. 댓글에 아이콘·이름·설명을 스냅샷으로 저장하며 편집·삭제로 변경하거나 환불하지 않는다.
- 최종 점수·주사위 수·재굴림·가하는 피해 효과는 `effect_stat_id=0`이면 `스탯 제한 없음`, 양수면 동적 상태 설정의 해당 ID에 한정한다. 복합 판정은 구성 스탯 중 해당 ID가 포함되면 적용하며, 받는 피해 효과는 항상 스탯 제한이 없다. 삭제된 스탯 ID는 전체 적용으로 대체하지 않고 관리자가 다시 지정할 때까지 사용을 막는다.
- 사용 가능 여부는 폼에서 안내하되, 작성 시 보유·활성·판정 조건·게시판 범위·기간 제한을 서버에서 재검증한다. 사용량은 성공한 게시글의 고유 식별자로 멱등하게 차감한다.
- 관리자 POST는 관리자 권한, demo 제한, CSRF 토큰을 확인하고 입력값을 서버에서 검증한다. 특성 아이콘은 래스터 파일 업로드 또는 HTTPS 외부 URL을 지원하며, 외부 이미지는 내려받지 않고 브라우저에서 직접 표시한다.
- 사용자 프로필과 게시글에는 HTML을 이스케이프해 출력한다. 과거 전투 결과는 특성의 당시 이름·효과 스냅샷을 사용한다.
- 댓글 폼·저장·표시는 MMB의 `bbs_comment_form_action_options`, `bbs_comment_form_after_action`, `bbs_custom_action`, `bbs_comment_after`, `bbs_view_row_extra` 훅을 사용하고 코어/스킨 파일은 수정하지 않는다.
